## 1. 찾아서 고친 버그 (승인 필요한 변경)
- **무엇**: 권한 목록을 문자열로 이어 붙여 비교할 때 정렬 순서가 DB 기본 정렬 규칙을 따랐습니다. 로컬 테스트 DB(C 정렬)에서는 문제가 없었지만, Supabase 기본(en-US)에서는 순서가 달라져 같은 권한인데도 "다르다"고 판단했습니다.
- **영향(고치기 전)**: 운영에 그대로 돌렸다면 ① 적용 SQL의 사전 점검이 실패해 **적용 자체가 중단**(데이터 변경 없이 멈춤), ② 되돌리기 자체 점검이 항상 실패, ③ 검증 SQL이 엉뚱한 FAIL을 냄. 권한이 잘못 바뀌는 위험은 없었습니다(멈추는 쪽으로만 실패).
- **고친 방법**: 비교용 정렬에 `collate "C"`를 지정 (커밋 e7e4248). **부여·회수하는 권한 내용은 한 줄도 바뀌지 않았고**, 비교 문자열의 정렬만 고정했습니다.
- **재확인**: 로컬 C 정렬 DB, 로컬 ICU en-US DB, 실제 테스트 프로젝트 세 곳 모두 통과.
- 현재 파일 지문(sha256 앞 12자리): migrate `b7594c7828c8` / rollback `c8438f9f5194` / verify `9344ae1e67ae`

## 3. 검증 못 한 것 (PASS 아님)
- service_role(비밀 키) API 경로 — 비밀 키를 쓰지 않는 원칙 때문에 미확인. SQL 편집기(postgres) 경로는 확인함.
- 운영 환경에서 실제 월요일 일정으로 도는 자동 추첨 — 테스트에서는 1분짜리 작업으로 실제 pg_cron 실행만 확인.
- 실제 화면을 사람이 눌러 보는 확인(지도·운영자 화면 UI) — 함수 호출 수준까지만 확인.
- 운영 DB 자체 — 당연히 손대지 않음. 운영 적용 후 체크리스트로 확인 필요.
