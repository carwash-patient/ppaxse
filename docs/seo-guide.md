# 검색 유입 작업 안내 (구글·네이버)

참고 사례: Vaultaire (광고비 0원, 구글 검색 유입으로 성장). 핵심은 **"이미 검색하고 있는 사람"을 빡세 사이트로 데려오는 것**입니다.

## 1. 무엇이 만들어지나

| 주소 | 내용 | 노리는 검색어 예 |
|---|---|---|
| `ppaxse.com/wash/` | 전국 시·도 목록 | 전국 세차장 |
| `ppaxse.com/wash/인천/` | 인천 시·군·구 목록 | 인천 세차장 |
| `ppaxse.com/wash/인천/서해구/` | 그 지역 세차장 전체 목록 | 서해구 세차장, 서해구 셀프세차 |
| `ppaxse.com/wash/인천/셀프세차/` | 시·도 종류별 목록 | 인천 셀프세차장, 인천 노터치세차 |
| `ppaxse.com/guide/글주소/` | 세차 가이드 글 | 겨울 셀프세차 방법 |

- 모든 페이지는 **처음부터 내용이 들어 있는 HTML**이라 구글·네이버가 읽을 수 있습니다. (지도 화면은 자바스크립트로 그려서 검색엔진이 잘 못 읽음)
- 페이지마다 **한마디 남기기(기프티콘 추첨)** 버튼이 위·아래에 있습니다. 영상의 "글 끝 다운로드 버튼"에 해당합니다.
- `wash/`, `guide/`, `sitemap.xml`, `robots.txt`는 **자동으로 만들어지는 파일**입니다. 직접 고치지 마세요. 고칠 곳은 `tools/build_seo.py`(틀)와 `guide-src/`(원고)입니다.

## 2. 자동 갱신

- GitHub Actions(`.github/workflows/build-seo.yml`)가 **매일 새벽 3시 10분**에 Supabase의 승인된 세차장으로 페이지를 다시 만듭니다.
- 운영자가 세차장을 승인·수정·폐업 처리하면 다음 날 새벽 검색용 페이지에 반영됩니다.
- 바뀐 게 없으면 커밋하지 않습니다.
- **새 주소 자동 알림(IndexNow)**: 빌드 뒤 새로 공개되거나 고친 주소를 `tools/indexnow.py`가 네이버(·빙 등)에 자동으로 알립니다. 서치어드바이저에서 '웹 페이지 수집'을 직접 누르지 않아도 됩니다. 키 파일 `9eeeaf1be380ad7c5356267a519e1bf9.txt`(사이트 맨 위)는 지우지 마세요.
- **구글**: 구글은 IndexNow를 쓰지 않습니다. 대신 사이트맵에 가이드 글의 날짜(lastmod)가 들어가 있어, 서치콘솔에 사이트맵만 한 번 제출해 두면 새 글을 스스로 찾아갑니다.

## 3. 가이드 글 쓰는 법

1. `guide-src/날짜-영문주소.html` 파일을 만듭니다 (예: `2026-11-18-foam-gun.html`).
2. 맨 위에 아래 4줄을 씁니다.
   ```
   <!-- slug: foam-gun -->
   <!-- title: 글 제목 -->
   <!-- description: 검색 결과에 보일 한두 문장 설명 -->
   <!-- date: 2026-11-18 -->
   ```
   잠시 숨기려면 `<!-- draft: yes -->` 한 줄을 더 넣습니다.
   필요하면 아래 줄도 넣습니다 (없어도 됨).
   ```
   <!-- category: 입문 -->   목록의 꼬리표·분류 버튼. 입문 / 차 상태별 / 계절 / 더 깔끔하게
   <!-- pin: 1 -->           목록 맨 위 '처음이라면 이것부터'에 숫자 순서로 고정
   ```
   - **예약 공개**: `date`가 오늘(한국 시간)보다 뒤면 숨겨 두었다가, 그날 새벽 3시 10분 자동 실행 때 공개됩니다. 미리 올려 두면 됩니다.
   - 단, 저장소가 공개라서 공개 전 원고도 GitHub에서는 보입니다.
   - 올린 지 3일 안 된 글은 목록에 '새 글'로 표시됩니다.
3. 그 아래에 본문을 `<p>`, `<h2>`, `<ul>`, `<ol>`, `<div class="tip">` 로 씁니다.
4. main에 올리면 Actions가 바로 페이지를 만듭니다.

### 글 원칙 — 가이드 글 규칙은 이 문서 하나가 기준입니다
매일 아침 클라우드 예약 작업('빡세 세차 가이드 글 초안')과 운영자 컴퓨터의 Claude(ppaxse-guide 스킬)가 모두 이 문서를 따릅니다. 규칙을 바꿀 때는 여기만 고칩니다.

**1) 공개 속도와 날짜** (운영자 결정 2026-11-18·11-19)
- 가이드 글이 **60편이 될 때까지 하루 2편, 60편부터 하루 1편**을 꾸준히 공개합니다. (예외: 목록을 처음 채운 2026-11-18 묶음)
- 날짜는 `python tools/guide_tools.py plan`으로 정합니다. 내일부터 7일 동안 하루 정원이 비는 자리를 알려 주고, 그 수만큼(최대 10편) 씁니다. 이렇게 일주일치를 미리 채워 두면 하루이틀 놓쳐도 공개가 끊기지 않습니다.
- 이미 예약된 글은 뒤로 밀지 않습니다. 올리기 직전에 `git pull` 후 다시 `plan`/`next-date`를 돌려, 그사이 다른 글이 그 날짜를 채웠으면 원고의 `date`를 다음 빈 날로 바꿉니다.
- 아직 공개 전인 글로는 링크를 걸지 않습니다 (`python tools/guide_tools.py check-links`로 확인). 그 글이 공개된 뒤 `updated` 날짜와 함께 링크를 추가합니다.

**2) 주제 고르기**
- 쓸 순서는 `docs/guide-topics.md`(주제 순서표)를 위에서부터 따릅니다. 아래는 그 표를 만들거나 새 후보를 추가할 때의 기준입니다.
- `docs/guide-keywords.md`(네이버 검색량 표, 운영자 컴퓨터가 7일마다 갱신)의 "가이드 글감(빈자리)"에서 검색량이 큰 것부터 고르고, 관련 검색어를 묶어 한 글로 만듭니다(예: 노터치자동세차+노브러쉬+자동세차).
- 표의 빈자리 표시는 대략 비교라서 `python tools/guide_tools.py titles`로 이미 쓴 글과 겹치는지 다시 봅니다. 겹치면 각도를 바꿉니다(예: '차이' 글이 있으면 '이용법' 글).
- 지도에 있는 세차장 종류(셀프·손세차·노터치·자동세차·디테일링)와 이어지는 주제가 우선입니다. 쇼핑 의도가 강한 검색어(용품·세트)는 특정 상품 추천 없이 쓰거나 미룹니다. 예약·결제 이야기는 쓰지 않습니다.
- 계절에 맞는 주제가 표에 있으면 먼저 써도 됩니다. 표가 비면 비슷한 결의 주제를 정하되, 고른 이유를 운영자에게 알립니다.

**3) 원고 형식**
- 맨 위: `slug`, `title`, `description`, `date`, `category`(입문 / 차 상태별 / 계절 / 더 깔끔하게) 5줄.
- 제목·첫 문단·소제목에 묶은 검색어를 자연스럽게 넣습니다. 제목에 "정답", "무조건", "반드시" 같은 단정 표현은 피합니다.
- 본문은 `<p>`, `<h2>`, `<ul>`/`<ol>`, `<div class="tip">💡 …</div>`만 씁니다(`<h1>`·지도 버튼은 빌드가 붙임). 분량은 본문 한글 1,500~2,500자 정도.
- 해요체, 짧은 문장. 첫 문단에서 무엇을 알려 주는지(또는 결론)를 먼저 말합니다.
- 링크: 다른 가이드 `../slug/`, 지역 목록 `../../wash/`. 끝 부분에 "내 주변 ○○ 세차장 찾기" 같은 소제목으로 빡세 지도·지역 목록을 안내하고, 다녀온 곳 정보를 한마디로 남겨 달라고 부탁합니다. 과장된 홍보 문구는 쓰지 않습니다.

**4) 글의 태도 — 세차에는 '정답'이 없다** (운영자가 가장 중요하게 여기는 부분)
- 말의 세기를 세 단계로 나눕니다.
  1. 보편적 사실·논리적으로 분명한 것(예: 제설제 염분은 부식을 돕는다): 분명하게 말해도 됩니다.
  2. 통상적으로 많이 쓰는 방법: "많은 분들이 ~해요"처럼 먼저 내세우되, 다른 방법과 그 이유도 짧게 소개합니다.
  3. 통상적이라 보기 어렵거나 논란이 있을 만한 것: "정답이라기보다 빡세가 생각하는 해답에 가까워요" 같은 느낌으로 씁니다.
- 한 가지 방법만 들고 단정하지 않습니다. 그렇다고 이도 저도 아닌 글은 안 됩니다. 기본으로 권하는 방법을 분명히 세우고, 다른 방법은 "이런 방법도 있어요"로 덧붙입니다.

**5) 사실과 숫자**
- 지어낸 숫자·통계·후기·인용·1인칭 경험담("제가 해 보니") 금지. 의견은 "빡세는 ~라고 생각해요", "~하는 분들이 많아요"로 씁니다. 운영자가 준 실제 경험은 "빡세 운영자는 ~했어요"로 넣습니다.
- 가격·시간처럼 세차장마다 다른 값은 숫자로 쓰지 않고 "세차장마다 달라요 + 확인하는 법"으로 씁니다. 기계·제품마다 다른 사용법은 "현장 안내·설명서를 따르세요"로 씁니다. 특정 제품·브랜드 추천 금지.
- 확실하지 않은 사실은 웹에서 확인하고, 그래도 불확실하면 빼거나 의견으로 씁니다. 확인한 출처는 운영자에게 알립니다. 화학제품·전기차처럼 안전과 관련된 내용은 보수적으로 씁니다.

**6) 올리는 절차**
- 운영자에게 미리보기(휴대폰 화면)와 원고 전체를 보여 주고 **"올려"라는 답을 받은 뒤에만** 올립니다. 확인 전에는 GitHub에 올리지 않습니다(브랜치 포함).
- 올릴 때: `git pull` → 날짜·링크 재확인(1번) → 원고 파일만 `git add` → 한국어 커밋 메시지(무엇을, 언제 공개) → `git push origin main`. 다른 작업이 먼저 올려 push가 거절되면 `git pull --rebase` 후 다시 push합니다.
- 확인: GitHub Actions '검색용 페이지 만들기' 성공, 예약 글 주소는 404(공개 전 정상)·오늘 글은 200.

## 4. 검색엔진 등록 (운영자가 한 번만)

### 구글 서치콘솔
1. https://search.google.com/search-console 접속 → ppaxse@gmail.com 으로 로그인
2. **속성 추가 → '도메인'** 선택 → `ppaxse.com` 입력
3. 보여주는 TXT 값을 복사 → **가비아 → DNS 관리 → ppaxse.com → TXT 레코드 추가** (호스트 `@`)
4. 몇 분~몇 시간 뒤 서치콘솔에서 '확인'
5. 왼쪽 **Sitemaps** → `sitemap.xml` 입력 → 제출

### 네이버 서치어드바이저
1. https://searchadvisor.naver.com 접속 → 웹마스터 도구 → 사이트 등록 `https://ppaxse.com`
2. 소유 확인은 **HTML 태그** 방식을 고르고, 나온 `<meta name="naver-site-verification" ...>` 태그를 Claude에게 주면 `index.html`에 넣어 드립니다.
3. 확인 후 **요청 → 사이트맵 제출** → `https://ppaxse.com/sitemap.xml`
4. **요청 → 웹 페이지 수집**에 새 가이드 글 주소를 넣으면 더 빨리 반영됩니다.

## 5. 매일 아침 루틴 (데이터가 2~4주 쌓인 뒤)
1. 서치콘솔 → 실적 → **노출은 많은데 클릭이 0이거나 적은 검색어**를 고릅니다.
2. 그 검색어에 답하는 가이드 1편을 씁니다 (AI에게 맡기고 운영자가 확인).
3. 이미 있는 글·지역 페이지와 서로 연결합니다.
